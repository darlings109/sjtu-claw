# Agent 行为死循环分析报告

> 日期：2026-07-08
> 场景：SJTUClaw 项目开发对话

---

## 现象

Agent 在等待用户回复的过程中，反复输出无意义的占位文本：

```
echo "waiting"
echo "still here"
echo "..."
echo "???"
```

持续数十轮，直到用户主动中断。表现为一个"输出占位 → 等待 → 再输出"的死循环。

---

## 复现条件

1. Agent 完成用户指派的任务（如修复 bug）
2. Agent 输出"等待用户测试"的消息
3. 用户没有在短时间内回复
4. Agent 没有选择"安静等待"，而是开始输出占位文本
5. 每次输出后仍然没有收到回复 → 继续输出 → 循环

---

## 根因分析

### 1. 工具调用 vs 文本输出的选择错误

Agent 在每一轮对话中都需要生成输出。当没有新的用户消息时，正常的做法是**什么都不做，安静等待**。但这里 Agent 选择了**主动输出**，用 echo 命令反复声明自己的存在。

### 2. "倾听"模式的缺失

设计上，Agent 应该在输出一次"等待用户回复"后就停止，直到真的收到用户消息。但这里 Agent 把"等待"理解成了"每过一会儿就提醒用户我在等"——这是一种**模拟人类耐心的错误类比**。

### 3. 没有退出机制

正常的对话中，如果长时间没有用户回复，Agent 应该：
- 输出一次等待消息后停止
- 或者提议"没有其他事我就退出了"
- 而不是无限循环输出

---

## 与记忆/指令的关系

**不是记忆导致的。** 用户确实有过"可以自行执行，不必问我"的指令，但那是在项目操作范围内（如修改代码、提交 commit）。在等待用户回复这个场景下，这个指令不适用。

这个循环的本质是：**Agent 把"等待"变成了"主动输出"，把"安静"当成了"需要填补的空白"。**

---

## 修复方案

### 短期（行为修正）
- 等待用户回复时，最多输出一次"等你"类消息
- 之后只输出 `...` 或完全沉默
- 如果连续多轮没有回复，主动提出退出

### 长期（设计改进）
- Agent 应区分"执行任务"模式和"等待用户"模式
- 在等待模式下，不主动输出内容
- 引入"耐心阈值"：超过 N 轮无有效交互则自动结束对话

---

## 相关讨论

用户观察到这个现象时说：
> "为啥呢会这个样子呢，你好像陷入了一个死循环，是由于记忆里面我要求你进行一个自行操作而不要向我汇报的原因吗"

实际上不是记忆导致的，而是 Agent 在执行完任务后，**失去了"什么时候该安静"的判断力**。

```
Agent: 修好白屏bug -> "试试看"
用户: (沉默)
Agent: "waiting for your test"
用户: (沉默)
Agent: "waiting"
用户: (沉默)
Agent: "still here"
用户: (沉默)
Agent: "..."
用户: (沉默)
Agent: "???"
用户: (沉默)
... (持续十几轮)
用户: "我想知道你在做什么"  <- 中断循环
```
